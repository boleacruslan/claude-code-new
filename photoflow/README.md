# photoflow

Пакетный отбор (куллинг) и ретушь кожи для событийной съёмки. Работает локально,
без интернета и подписки, все пороги видны и настраиваются.

Три команды:

- **`cull`** — раскладывает съёмку по папкам `keep / maybe / reject`, оценивая
  фокус по глазам, экспозицию, закрытые глаза и дубли внутри серий.
- **`retouch`** — сглаживает кожу и смягчает морщины, сохраняя поры.
- **`style`** — учится на твоих прошлых каталогах Lightroom и предсказывает
  develop-настройки для новой съёмки.

Плюс `calibrate` — показывает распределение метрик по твоей съёмке, чтобы
подобрать пороги под свою оптику и стиль.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Версии в `requirements.txt` закреплены не из осторожности, а по необходимости:
в mediapipe 1.x убрали API `solutions` и веса моделей, а в OpenCV 5.x — каскады.
На указанной связке модели лежат внутри пакетов, и инструмент работает офлайн.

## Формат файлов

`cull` и `retouch` читают JPEG, TIFF, PNG. **RAW они не читают** — при встрече
предупреждают и пропускают. `style` читает NEF и прочий RAW напрямую через rawpy,
потому что ему нужен кадр до обработки.

Для отбора это скорее правильный порядок работы: включи в камере `RAW + JPEG`
(или выгони JPEG-превью пакетом), отбирай по JPEG, а проявляй победителей из NEF
в Lightroom. Отбор по превью в разы быстрее, а решение «годится / не годится»
от проявки не зависит.

## Отбор

```bash
# посмотреть, что будет, ничего не трогая
python -m photoflow cull /путь/к/съёмке --dry-run

# разложить копии по папкам keep / maybe / reject
python -m photoflow cull /путь/к/съёмке -o /путь/отбор
```

Оригиналы не удаляются никогда. По умолчанию файлы **копируются**; `--action move`
переносит, `--action link` делает симлинки, `--action none` только считает.

Рядом с результатом появляется `_report/index.html` — контактный лист с
миниатюрами, оценками и причинами по каждому кадру, и `cull.csv` со всеми
метриками для разбора в Excel.

### Что именно оценивается

| Метрика | Как считается |
|---|---|
| Фокус | Резкость **области глаз** в нативном разрешении файла |
| Закрытые глаза | Eye Aspect Ratio по ландмаркам век, отдельно на каждом лице |
| Экспозиция | Яркость кожи главного героя + выбитые света и провалы по всему кадру |
| Дубли | Перцептивный хеш + разрыв по времени съёмки из EXIF |

Два решения, которые стоит объяснить, потому что они влияют на результат сильнее всего:

**Резкость меряется на полном разрешении, а не на превью.** Если ужать кадр с
8256px до 1600px, промах фокуса, очевидный при 100%, размажется в пару пикселей и
станет неотличим от резкого. Проверено: на нативном разрешении метрика разделяет
резкий и размытый кадр в 6 раз, на ужатом — почти не реагирует.

**Пороги считаются от самой съёмки, а не заданы числом.** Абсолютное значение
резкости зависит от тушки, объектива и дистанции, поэтому фиксированный порог
либо выбраковывает всю съёмку на мягкой оптике, либо пропускает всё подряд.
Скрипт берёт перцентили твоей папки и меряет каждый кадр относительно них.

Из этого следует допущение: **типичный кадр в папке считается пригодным.** На
реальной съёмке это верно. Если скормить папку, где заведомо большая часть брака,
калибровка сместится и брак будет выглядеть нормой.

### Групповые и ростовые кадры

MediaPipe оценивает лицо по его доле в кадре, а не в пикселях, поэтому гостей на
общем плане он просто не видит — и апскейл кадра тут не помогает вообще. Скрипт
режет кадр на перекрывающиеся тайлы, где каждое лицо становится крупным
относительно своего тайла, и склеивает найденное с дедупликацией.

Тайловый проход включается только когда обычный ничего не нашёл или нашёл лишь
мелкие лица, так что портреты крупным планом остаются на быстром пути.
`--tiles 3` копает глубже на больших групповых, `--tiles 0` выключает.

### Подстройка

```bash
python -m photoflow calibrate /путь/к/съёмке --limit 200
```

Покажет перцентили метрик и сколько кадров попадёт в каждую корзину при текущих
настройках. Дальше крути `--keep-score` (по умолчанию 62), `--reject-score` (38),
`--ear-closed` (0.18) и `--burst-gap` (3 сек).

## Ретушь

```bash
# начни с превью «до/после», чтобы подобрать силу
python -m photoflow retouch /путь/keep -o /путь/ретушь --preview -s 0.6

# потом всю папку
python -m photoflow retouch /путь/keep -o /путь/ретушь -s 0.6
```

Кадр раскладывается на три частотные полосы:

- **base** — тон и светотень, край-сохраняющий фильтр;
- **mid** — пятна, неровности тона, линии морщин: **эту полосу и давим**, причём
  тёмную её половину сильнее, потому что морщина и есть тёмная деталь;
- **fine** — поры, ресницы, щетина: сохраняется почти полностью (90%).

Поэтому не получается «пластик»: обычное одношаговое размытие убивает поры вместе
с морщинами, здесь поры остаются нетронутыми.

Обрабатывается только кожа внутри растушёванной маски: глаза, брови, губы, волосы
и фон исключены. Проверено замером — при силе 0.6 среднее изменение на коже
примерно вчетверо больше, чем на глазах и губах, и почти ноль за пределами лица.

Вся частотная математика идёт на приведённом размере, поэтому лицо в 300px и в
3000px обрабатываются одинаково по сути, а не по пикселям.

### Ручки

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `-s, --strength` | 0.6 | Общая сила. 0.4 — едва заметно, 1.0 — сильно |
| `--smooth-threshold` | 0.45 | **Главная ручка.** Контраст, который фильтр не трогает. Ниже — морщины считаются краями и остаются; выше — начинает съедать светотень лица |
| `--wrinkle` | 0.35 | Сколько тёмной средней полосы оставить. Ниже — морщины глаже |
| `--texture` | 0.90 | Сколько пор оставить. Не опускай сильно, иначе пластик |
| `--under-eye` | 0 (выкл) | Осветление области под глазами |

EXIF переносится в результат. Оригиналы не перезаписываются — результат кладётся
в отдельную папку с суффиксом.

## Скорость

На 8 процессах: отбор — порядка сотни кадров в минуту на 24MP JPEG, ретушь —
около 8 секунд на кадр 24MP на ядро. Съёмка на 2000 кадров отбирается примерно за
полчаса, ретушится дольше — разумно ретушировать только папку `keep`.

`-j N` задаёт число процессов.

## Обучение на твоём стиле обработки

Третья команда — `style`. Она учится на твоих прошлых съёмках и предсказывает
develop-настройки Lightroom для новой. Не один пресет на всех: для каждого кадра
свои значения.

Результат — XMP-сайдкары, то есть обычные ползунки Lightroom, которые ты дальше
двигаешь руками. Пиксели не запекаются.

### Порядок работы

```bash
# 1. Разведка: что вообще читается из каталога и что в нём варьируется
python -m photoflow style inspect --catalog /path/Wedding2025.lrcat

# 2. Проверить, что NEF декодируется на этой машине
python -m photoflow style check-raw /path/DSC_0001.NEF

# 3. Обучение (каталог открывается только на чтение, Lightroom можно не закрывать)
python -m photoflow style learn --catalog /path/Wedding2025.lrcat \
    --images-root /path/к/NEF -o style.joblib

# 4. Применение к новой съёмке
python -m photoflow style apply /path/новая_съёмка --model style.joblib --dry-run
python -m photoflow style apply /path/новая_съёмка --model style.joblib
```

Дальше в Lightroom: импортировать кадры либо выделить их и
`Metadata > Read Metadata from File`.

**Начинай с `inspect`.** Схему каталога Adobe не документирует, настройки лежат
в нём сериализованным Lua-блобом, и разбор — обоснованное предположение, пока не
встретится с настоящим каталогом. `inspect` отвечает на один вопрос: правки
действительно прочитались или нет. Если схема не совпала — запасной путь через
`Metadata > Save Metadata to File` и обучение по папке с сайдкарами.

### Два правила, которые не дают отчёту врать

**Проверка разбивается по съёмкам, а не по кадрам.** Соседние кадры одной серии
почти одинаковы. При случайном разбиении братья по серии попадут и в обучение, и
в проверку, цифры получатся прекрасные, а на новой свадьбе модель развалится. Все
числа в отчёте получены на свадьбах, которых модель не видела целиком. Замер на
симуляции: случайное разбиение завышало точность на 14%.

**Каждый параметр обязан побить базу** — предсказание твоего же медианного
значения. Это бесплатно и на удивление сильно. Где модель базу не бьёт, параметр
понижается до константы и помечается как невыученный. Проверено: на синтетике с
намеренно шумовым параметром модель его отвергла.

Отчёт выглядит так (симуляция, 6 свадеб, проверка на отложенной):

```
   parameter                         n     error  baseline    gain
   Temperature                     240     84.26    497.07     83%
   Shadows2012                     240      4.38      9.53     54%
   Exposure2012                    240      0.21      0.40     47%

not learned - emitted as your usual value instead:
   Tint                         no gain over baseline (6.19 vs 6.08)
```

Ошибка — в единицах самого ползунка, потому что «0.21 EV» фотографу понятно, а R²
нет.

### Честно о точности

Числа выше получены на **симулированном** архиве, где связь «кадр → правка»
заложена мной и она чистая. Реальная обработка содержит художественный произвол,
который из кадра не выводится вообще: настроение съёмки, пожелания пары, то,
каким ты был в тот вечер. На настоящем архиве ошибки будут больше, и часть
параметров окажется невыученной — это не поломка, а честный ответ.

Лучше всего предсказываются экспозиция, баланс белого и тон: там решение диктует
сам кадр. Хуже — кривые и HSL, где выбор свободный.

### Что нужно от тебя

- **Каталоги** `.lrcat` или XMP-сайдкары.
- **Исходники NEF** — модели нужно видеть кадр ДО обработки. Рендер строго
  фиксированный (`no_auto_bright`, баланс белого камеры): адаптивный рендер
  молча исправил бы ровно те различия, которые модель должна объяснять.
  Множители баланса белого камеры идут в признаки — без них абсолютные Кельвины
  не предсказать.
- **Минимум 3 съёмки**, лучше 5–10. На меньшем проверять не на чем, и `learn`
  об этом предупредит.

### Чему это не научится

- Локальные правки — кисти, градиенты, маски, ИИ-маски. Это решения про
  конкретный кадр, устойчивой связи со статистикой изображения у них нет.
- Кадрирование и композиция.
- Ретушь — для неё отдельная команда `retouch`.

## Чего он не делает

- Не читает RAW.
- Не оценивает композицию при отборе.
- Не оценивает композицию, эмоцию и сюжет. Отличить «технически годный» от
  «того самого» кадра он не может — финальный отбор остаётся за тобой.
- Не убирает отдельные объекты, не правит фигуру, не делает локальную ретушь.

Поэтому режим по умолчанию — копирование с отчётом, а не удаление: скрипт
сокращает объём ручного просмотра, но не выносит окончательный приговор.
